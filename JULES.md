## 🏛️ 1. Asynchronous Git & GitHub Workflow

Google Jules operates asynchronously on GitHub issues, branches, and pull requests within the **JudgeGuard Master Orchestration** ecosystem.

1. **Ticket Admission (Layer 000 Gate):**
   - Before starting work on any GitHub issue or task, ensure `TICKET.md` reflects the active objective.
   - Run pre-action verification:
     ```bash
     ./gemini_cli.sh "[ISSUE_OR_TASK_NAME]"
     ```
2. **Branching & Checkpoint Commits:**
   - Always work in dedicated task branches (`jules/[feature-or-fix]`).
   - Every commit must follow the Master Orchestration format:
     `checkpoint: [ACTION]`
   - Record the commit hash in `WORK_LOG.md`.
3. **Atomic Task Chunking:**
   - Keep open tasks in `WORK_LOG.md` at or below 5. Close completed tasks with `✅ Completed`.

## 🧹 2. Token Cleaning & Context Hygiene Protocol

Jules operates in cloud-hosted virtual machines with token budgets. Jules MUST enforce strict context reduction:

1. **Excluded Context Paths:**
   - NEVER ingest or load into agent context:
     - `local_py/**` (180MB+ of legacy Google API discovery JSONs)
     - `.venv/**`, `node_modules/**`, `dist/**`, `build/**`
     - `.git/**`, `.cache/**`, `exports/**`, `*.so`, `*.pyc`
2. **Targeted Code Navigation:**
   - Use ripgrep or symbol-level queries instead of dumping file hierarchies.
   - When preparing diffs, run:
     ```bash
     python3 git_bolt_jules_gate.py clean-diff
     ```
   - Before committing, verify staged changes are clean:
     ```bash
     python3 git_bolt_jules_gate.py audit
     ```
